Copias Fantasma vs Copias Reales (Clone)

Uno de los errores más comunes en la Programación Orientada a Objetos en Java sucede al intentar duplicar un objeto. Igualar dos variables (objetoA = objetoB) no hace lo que la mayoría de los principiantes creen.

1. La Copia por Referencia (Ghost Copy)

Punteros a la Memoria

Cuando haces Producto p2 = p1;, Java NO crea un nuevo producto en la memoria. Simplemente crea una nueva "etiqueta" (variable) que apunta al mismo objeto original. Esto significa que si modificas p2, ¡también estarás modificando a p1, porque son la misma entidad física en la RAM!

// Creamos un objeto físico real (con "new")
Producto p1 = new Producto("TV", 500.0);

// COPIA FANTASMA: Solo copiamos el puntero
Producto p2 = p1;

// Modificamos p2...
p2.setPrecio(100.0);

// ¡OH SORPRESA! p1 también fue modificado
System.out.println(p1.getPrecio()); // Imprime: 100.0

2. La Copia Real (Deep / Shallow Clone)

Para duplicar un objeto de verdad, debes forzar a Java a reservar nueva memoria para el segundo objeto. Existen múltiples formas de hacerlo, como implementar un constructor de copia o usar el método clone() de la interfaz Cloneable.

Solución Básica: Constructor de Copia

CopiaSegura.java 
public class Producto {
    private String nombre;
    private double precio;
    
    // Constructor normal
    public Producto(String nombre, double precio) {
        this.nombre = nombre;
        this.precio = precio;
    }
    
    // CONSTRUCTOR DE COPIA
    public Producto(Producto original) {
        this.nombre = original.nombre;
        this.precio = original.precio;
    }
}

// ---- EN EL MAIN ----
Producto p1 = new Producto("TV", 500.0);

// COPIA REAL: Usamos 'new' para reservar nueva memoria
Producto p2 = new Producto(p1);

p2.setPrecio(100.0);
System.out.println(p1.getPrecio()); // Imprime: 500.0 (¡p1 quedó intacto!)

Solución Avanzada: Interfaz Cloneable

Java ofrece un mecanismo nativo para clonar objetos a través de la interfaz marcador Cloneable y sobrescribiendo el método clone() de la clase Object.

ClonacionNativa.java 
// 1. Implementar la interfaz Cloneable
public class Producto implements Cloneable {
    private String nombre;
    private double precio;
    
    public Producto(String nombre, double precio) {
        this.nombre = nombre;
        this.precio = precio;
    }
    
    // 2. Sobrescribir el método clone()
    @Override
    public Producto clone() {
        try {
            // Llama al clone nativo (hace una shallow copy automática de los atributos)
            return (Producto) super.clone();
        } catch (CloneNotSupportedException e) {
            throw new AssertionError(); // Nunca debería ocurrir si implementas Cloneable
        }
    }
}

// ---- EN EL MAIN ----
Producto p1 = new Producto("Laptop", 1200.0);

// CLONACIÓN NATIVA: Se crea un objeto nuevo en memoria
Producto p3 = p1.clone();

p3.setPrecio(999.0);
System.out.println(p1.getPrecio()); // Imprime: 1200.0 (p1 queda intacto)

Nota: super.clone() realiza una copia superficial (Shallow Copy). Si tu clase tuviera atributos que fueran otros objetos complejos (ej. listas u otros objetos propios), tendrías que clonarlos manualmente dentro del método clone() para lograr una copia profunda (Deep Copy).
