17. Fundamentos de Bases de Datos Relacionales y SQL

Mientras que los archivos de texto (.txt, .csv) o binarios (.dat) obligan a cargar y reescribir colecciones completas en memoria, un Sistema Gestor de Bases de Datos Relacionales (RDBMS) permite almacenar, relacionar, filtrar y actualizar millones de registros de forma segura, atómica (transacciones ACID) y estructurada mediante el lenguaje estándar SQL (Structured Query Language).

1. Conceptos Clave del Modelo Relacional

Tabla, Fila y Columna

Una Tabla (Entidad) equivale a una clase POJO en Java (ej. Cafe). Cada Columna (Atributo/Campo) representa una propiedad con su tipo de dato (Productor, Cantidad), y cada Fila (Tupla/Registro) es una instancia u objeto concreto guardado.

Clave Primaria (Primary Key - PK)

Identificador único e irrepetible de cada fila (ej. IDCafe o IDVariedad). Nunca puede ser NULL. Suele configurarse como AUTOINCREMENT (SQLite) o AUTO_INCREMENT (MySQL) para que el motor asigne el número automáticamente al insertar.

Clave Foránea (Foreign Key - FK)

Columna de una tabla hija que apunta a la PRIMARY KEY de otra tabla padre para establecer una relación y garantizar la integridad referencial (no puedes registrar un café con una variedad que no exista en VariedadCafe).

Modelo Entidad-Relación del Proyecto BaseDatos (Relación 1 a Muchos - 1:N)

En la base de datos informacion.db / informacion_db del proyecto, una Variedad de Café (ej. 1 - Caturra, 2 - Negro) puede estar asociada a muchos lotes de Café, pero cada lote de Café tiene una sola variedad:

TABLA PADRE: VariedadCafe 1
IDVariedad : INTEGER (PK, AI)
Descripcion : TEXT NOT NULL
Ejemplo de datos: (1, 'Caturra'), (2, 'Negro')
TABLA HIJA: Cafe N (Muchos)
IDCafe : INTEGER (PK, AI)
Productor : TEXT NOT NULL
VariedadCafe : INTEGER (FK → VariedadCafe.IDVariedad)
Cantidad : REAL NOT NULL
Ejemplo: (1, 'El chiringuito', 1, 2.5), (2, 'FincaSol', 2, 1.0)

2. SQLite vs MySQL: ¿Cuándo usar cada motor?

El proyecto BaseDatos implementa una arquitectura dual muy interesante: utiliza MySQL como servidor principal y SQLite como base de datos local de respaldo (fallback). Veamos sus diferencias técnicas:

Característica SQLite (Embebido / Local) MySQL / MariaDB (Cliente-Servidor)
Arquitectura Sin servidor (Serverless). Toda la BD reside en un único archivo en disco (informacion.db). Motor Cliente-Servidor que escucha peticiones por red en un puerto TCP (por defecto 3306).
URL JDBC jdbc:sqlite:informacion.db jdbc:mysql://localhost:3306/informacion_db
Autenticación No tiene usuarios ni contraseñas (depende de los permisos del archivo en el SO). Requiere usuario (ej. root), contraseña y permisos por host/base de datos.
Tipos de Datos Tipado dinámico por afinidad: INTEGER, TEXT, REAL, NUMERIC, BLOB. Tipado estricto: INT, VARCHAR(n), FLOAT, DOUBLE, DECIMAL, DATE.
Herramienta Visual DB Browser for SQLite XAMPP + phpMyAdmin / MySQL Workbench

3. SQL DDL (Data Definition Language): Creando las Tablas del Proyecto

El sublenguaje DDL (CREATE, ALTER, DROP) define la estructura de las tablas. Observa la pequeña diferencia sintáctica entre el autoincremento de SQLite (AUTOINCREMENT) y el de MySQL (AUTO_INCREMENT):

Esquema en SQLite (informacion.db) 
-- 1. Tabla Padre: VariedadCafe
CREATE TABLE "VariedadCafe" (
    "IDVariedad"  INTEGER NOT NULL,
    "Descripcion" TEXT NOT NULL,
    PRIMARY KEY("IDVariedad" AUTOINCREMENT)
);

-- 2. Tabla Hija: Cafe
CREATE TABLE "Cafe" (
    "IDCafe"       INTEGER,
    "Productor"    TEXT NOT NULL,
    "VariedadCafe" INTEGER NOT NULL,
    "Cantidad"     REAL NOT NULL,
    PRIMARY KEY("IDCafe" AUTOINCREMENT),
    FOREIGN KEY("VariedadCafe")
        REFERENCES "VariedadCafe"("IDVariedad")
);
Esquema en MySQL / XAMPP (informacion_db) 
CREATE DATABASE IF NOT EXISTS informacion_db;
USE informacion_db;

-- 1. Tabla Padre: VariedadCafe
CREATE TABLE VariedadCafe (
    IDVariedad INT NOT NULL AUTO_INCREMENT,
    Descripcion VARCHAR(100) NOT NULL,
    PRIMARY KEY (IDVariedad)
);

-- 2. Tabla Hija: Cafe
CREATE TABLE Cafe (
    IDCafe INT NOT NULL AUTO_INCREMENT,
    Productor VARCHAR(150) NOT NULL,
    VariedadCafe INT NOT NULL,
    Cantidad FLOAT NOT NULL,
    PRIMARY KEY (IDCafe),
    FOREIGN KEY (VariedadCafe)
        REFERENCES VariedadCafe(IDVariedad)
);

4. SQL DML & DQL: Las 4 Operaciones CRUD e INNER JOIN

Todo sistema de base de datos se apoya en el acrónimo CRUD: Create (INSERT), Read (SELECT), Update (UPDATE) y Delete (DELETE). Estas son exactamente las sentencias que ejecuta AdmonCafe.java:

Operaciones CRUD completas + INNER JOIN 
-- ==========================================
-- 1. CREATE (Insertar nuevos registros)
-- ==========================================
INSERT INTO VariedadCafe (Descripcion) VALUES ('Caturra');
INSERT INTO VariedadCafe (Descripcion) VALUES ('Negro');

INSERT INTO Cafe (Productor, VariedadCafe, Cantidad) VALUES ('El chiringuito', 1, 2.5);
INSERT INTO Cafe (Productor, VariedadCafe, Cantidad) VALUES ('FincaSol', 2, 1.0);

-- ==========================================
-- 2. READ (Consultar registros)
-- ==========================================
-- Consulta simple de toda la tabla
SELECT * FROM Cafe;

-- Consulta combinada (INNER JOIN) para ver el nombre de la variedad en lugar de solo su ID numérico
SELECT c.IDCafe, c.Productor, v.Descripcion AS NombreVariedad, c.Cantidad
FROM Cafe c
INNER JOIN VariedadCafe v ON c.VariedadCafe = v.IDVariedad
WHERE c.Cantidad >= 1.0
ORDER BY c.IDCafe ASC;

-- ==========================================
-- 3. UPDATE (Modificar un registro existente)
-- ¡NUNCA OLVIDES EL WHERE O ACTUALIZARÁS TODA LA TABLA!
-- ==========================================
UPDATE Cafe
SET Productor = 'Finca Sol Premium', VariedadCafe = 1, Cantidad = 4.75
WHERE IDCafe = 2;

-- ==========================================
-- 4. DELETE (Borrar un registro específico)
-- ¡NUNCA OLVIDES EL WHERE O VACIARÁS TODA LA TABLA!
-- ==========================================
DELETE FROM Cafe WHERE IDCafe = 2;
