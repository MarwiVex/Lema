JavaFX & Scene Builder: Guía Completa y Práctica

JavaFX es el toolkit moderno para el desarrollo de aplicaciones de escritorio enriquecidas (GUI) en Java. Separa limpiamente el diseño visual declarativo (archivos .fxml) de la lógica de negocio mediante controladores, permitiendo diseñar interfaces de alta calidad usando herramientas visuales como Scene Builder.

1. Conceptos Fundamentales: Stage, Scene y Nodos

Stage (El Escenario)

Representa la ventana principal del sistema operativo (borde, barra de título, botones de minimizar/cerrar). JavaFX te proporciona el primaryStage en el método start.

Scene (La Escena)

Es el contenedor de todo el contenido visual dentro del Stage. Un Stage solo muestra una Scene a la vez, pero puedes intercambiar escenas dinámicamente con transiciones o navegación.

Scene Graph & Nodes

Árbol jerárquico de elementos visuales (Layouts, Buttons, Labels, ComboBoxes). Todos derivan de Node y componen la vista cargada desde tu archivo FXML.

2. Flujo de Trabajo con Scene Builder

Gluon Scene Builder es el diseñador visual drag-and-drop de JavaFX. Para conectar lo que arrastras en pantalla con tu código Java, existen tres pilares:

  • Asignar el Controller: En el panel inferior izquierdo (Document > Controller), escribe la clase controladora con su paquete completo (ej. com.ejemplo.controllers.CalculadoraController).
  • Identificar Componentes (fx:id): En el panel derecho (Code > fx:id), dale un identificador a cada control que quieras manipular desde Java (ej. txtPantalla, lblEstado, btnSumar). Debe coincidir exactamente con el nombre de la variable anotada con @FXML.
  • Event Handlers (On Action): En el panel derecho (Code > On Action), escribe el nombre del método manejador con una almohadilla inicial (ej. #onDigitoClick o #onOperacionClick).

3. Componentes Básicos, Métodos Esenciales y ActionEvent

En JavaFX, casi todos los controles de texto descienden de Labeled o TextInputControl. Dominar sus métodos fundamentales es clave antes de construir pantallas complejas:

Label

Texto estático o dinámico para mostrar información al usuario.

lblMensaje.setText("Total: $500");
String txt = lblMensaje.getText();
lblMensaje.setVisible(false);

TextField

Caja de entrada de una sola línea editable por el usuario.

String entrada = txtNombre.getText();
txtNombre.setText("");
txtNombre.setPromptText("Ingresa...");
txtNombre.setEditable(false);

Button & ActionEvent

Dispara eventos al hacer clic o presionar Enter.

btnCalcular.setDisable(true);
btnCalcular.setText("Guardando...");
Button b = (Button) event.getSource();
String textoBtn = b.getText();

¿Qué es ActionEvent y para qué sirve?

Cuando un usuario hace clic en un botón, JavaFX crea un objeto ActionEvent. Mediante event.getSource() puedes saber exactamente qué botón fue presionado. Esto es sumamente útil porque te permite conectar muchos botones distintos al mismo método manejador sin tener que crear un método por cada botón.

@FXML
private void onBotonPresionado(ActionEvent event) {
    Button boton = (Button) event.getSource(); // Obtenemos el botón origen
    String texto = boton.getText(); // Obtenemos su etiqueta ("1", "2", "+", etc.)
}

4. Ejemplo Práctico: Calculadora con StringBuilder y ActionEvent

A continuación se muestra un ejemplo clásico y completo de una calculadora. Observa cómo usamos StringBuilder como buffer para concatenar los dígitos conforme el usuario pulsa botones, luego parseamos a números (Double.parseDouble) al realizar operaciones y actualizamos el TextField de salida:

CalculadoraController.java 
import javafx.event.ActionEvent;
import javafx.fxml.FXML;
import javafx.scene.control.Button;
import javafx.scene.control.Label;
import javafx.scene.control.TextField;

public class CalculadoraController {

    // Controles vinculados con fx:id desde Scene Builder
    @FXML private TextField txtPantalla;
    @FXML private Label lblOperacionPrevia;

    // Buffer en memoria para acumular los caracteres del número actual
    private StringBuilder bufferActual = new StringBuilder();
    private double primerOperando = 0.0;
    private String operador = "";
    private boolean inicioNuevoNumero = true;

    /**
     * UN SOLO MÉTODO PARA TODOS LOS DÍGITOS (0 al 9 y punto decimal).
     * En Scene Builder, asigna #onDigitoClick al "On Action" de todos los botones numéricos.
     */
    @FXML
    private void onDigitoClick(ActionEvent event) {
        Button btnPresionado = (Button) event.getSource();
        String digito = btnPresionado.getText();

        // Evitar múltiples puntos decimales
        if (digito.equals(".") && bufferActual.toString().contains(".")) {
            return;
        }

        if (inicioNuevoNumero) {
            bufferActual.setLength(0); // Limpiar buffer si empezamos un nuevo número
            inicioNuevoNumero = false;
        }

        // Concatenamos el dígito al buffer
        bufferActual.append(digito);
        
        // Reflejamos en la pantalla de texto
        txtPantalla.setText(bufferActual.toString());
    }

    /**
     * Maneja los operadores (+, -, *, /)
     */
    @FXML
    private void onOperacionClick(ActionEvent event) {
        if (bufferActual.length() == 0 && txtPantalla.getText().isEmpty()) return;

        Button btnOp = (Button) event.getSource();
        operador = btnOp.getText();

        // Convertimos el String del buffer a double para operar
        primerOperando = Double.parseDouble(txtPantalla.getText());
        lblOperacionPrevia.setText(primerOperando + " " + operador);
        inicioNuevoNumero = true;
    }

    /**
     * Calcula el resultado final al pulsar '='
     */
    @FXML
    private void onIgualClick(ActionEvent event) {
        if (operador.isEmpty() || bufferActual.length() == 0) return;

        double segundoOperando = Double.parseDouble(bufferActual.toString());
        double resultado = 0.0;

        switch (operador) {
            case "+": resultado = primerOperando + segundoOperando; break;
            case "-": resultado = primerOperando - segundoOperando; break;
            case "*": resultado = primerOperando * segundoOperando; break;
            case "/": 
                if (segundoOperando == 0) {
                    txtPantalla.setText("Error: Div 0");
                    lblOperacionPrevia.setText("");
                    bufferActual.setLength(0);
                    inicioNuevoNumero = true;
                    return;
                }
                resultado = primerOperando / segundoOperando; 
                break;
        }

        // Convertimos el resultado numérico a String para la UI
        txtPantalla.setText(String.valueOf(resultado));
        lblOperacionPrevia.setText(primerOperando + " " + operador + " " + segundoOperando + " =");

        // Preparamos para continuar operando con el resultado
        bufferActual.setLength(0);
        bufferActual.append(resultado);
        operador = "";
        inicioNuevoNumero = true;
    }

    /**
     * Limpia la pantalla y resetea el estado (Botón C)
     */
    @FXML
    private void onLimpiarClick(ActionEvent event) {
        bufferActual.setLength(0);
        primerOperando = 0.0;
        operador = "";
        txtPantalla.setText("0");
        lblOperacionPrevia.setText("");
        inicioNuevoNumero = true;
    }
}

5. Initializable vs Constructor: Diferencias Clave

¡Cuidado con el NullPointerException!

Cuando FXMLLoader procesa un archivo FXML, primero ejecuta el Constructor de la clase controladora. En este momento exacto, las variables con la anotación @FXML aún son null porque el archivo FXML todavía no ha inyectado los nodos en las variables. Por eso, NUNCA intentes hacer cosas como txtPantalla.setText() o cmbItems.setItems() en el constructor.

En el Constructor

  • Los campos @FXML son null.
  • No accedas a botones, tablas o combos aquí (lanzará NullPointerException).
  • Úsalo solo para instanciar estructuras puras de Java (ej. inicializar un ArrayList o inyección de dependencias).

En initialize()

  • Todos los campos @FXML ya están enlazados e inyectados.
  • Es el lugar idóneo para llenar ComboBox, configurar TableView y añadir listeners.
  • Se ejecuta automáticamente de forma garantizada tras cargar la vista.

6. Uso de Initializable con ComboBox y Objetos Personalizados

Para poblar un ComboBox con objetos complejos (no solo Strings simples) y controlar exactamente qué propiedad se muestra sin depender únicamente del método toString(), utilizamos setCellFactory y setButtonCell dentro de initialize:

Categoria.java (Modelo) 
public class Categoria {
    private int id;
    private String nombre;

    public Categoria(int id, String nombre) {
        this.id = id;
        this.nombre = nombre;
    }

    public int getId() { return id; }
    public String getNombre() { return nombre; }

    @Override
    public String toString() {
        return nombre; // Respaldo básico
    }
}
FormularioController.java 
import javafx.collections.FXCollections;
import javafx.collections.ObservableList;
import javafx.fxml.FXML;
import javafx.fxml.Initializable;
import javafx.scene.control.ComboBox;
import javafx.scene.control.Label;
import javafx.scene.control.ListCell;
import java.net.URL;
import java.util.ResourceBundle;

public class FormularioController implements Initializable {

    @FXML private ComboBox cmbCategorias;
    @FXML private Label lblSeleccion;

    @Override
    public void initialize(URL location, ResourceBundle resources) {
        // 1. Crear la lista observable de elementos
        ObservableList categorias = FXCollections.observableArrayList(
            new Categoria(1, "Tecnología y Gadgets"),
            new Categoria(2, "Libros y Educación"),
            new Categoria(3, "Hogar y Muebles")
        );

        // 2. Asignar los elementos al ComboBox
        cmbCategorias.setItems(categorias);

        // 3. Personalizar cómo se ven los ítems en el menú desplegable (CellFactory)
        cmbCategorias.setCellFactory(param -> new ListCell() {
            @Override
            protected void updateItem(Categoria item, boolean empty) {
                super.updateItem(item, empty);
                setText((empty || item == null) ? null : item.getId() + " - " + item.getNombre());
            }
        });

        // 4. Personalizar cómo se muestra el ítem seleccionado en el botón cerrado
        cmbCategorias.setButtonCell(new ListCell() {
            @Override
            protected void updateItem(Categoria item, boolean empty) {
                super.updateItem(item, empty);
                setText((empty || item == null) ? null : item.getNombre());
            }
        });

        // 5. Escuchar cambios de selección
        cmbCategorias.getSelectionModel().selectedItemProperty().addListener((obs, anterior, seleccionado) -> {
            if (seleccionado != null) {
                lblSeleccion.setText("Elegiste: " + seleccionado.getNombre() + " (ID: " + seleccionado.getId() + ")");
            }
        });
    }
}

7. Gestión de Múltiples Escenas y Ventanas (Launchers)

En aplicaciones del mundo real existen dos patrones principales para la navegación:

Opción A: Cambiar Escena en la Misma Ventana

Consiste en reemplazar el Scene actual del primaryStage por uno nuevo.

NavegacionController.java 
import javafx.event.ActionEvent;
import javafx.fxml.FXML;
import javafx.fxml.FXMLLoader;
import javafx.scene.Node;
import javafx.scene.Parent;
import javafx.scene.Scene;
import javafx.stage.Stage;
import java.io.IOException;

public class MenuController {

    @FXML
    private void onIrADetalle(ActionEvent event) {
        try {
            // Cargar el nuevo FXML
            Parent root = FXMLLoader.load(getClass().getResource("/vistas/DetalleView.fxml"));
            
            // Obtener el Stage actual desde el evento del botón
            Stage stage = (Stage) ((Node) event.getSource()).getScene().getWindow();
            
            // Reemplazar la escena actual
            stage.setScene(new Scene(root));
            stage.show();
        } catch (IOException e) {
            e.printStackTrace();
        }
    }
}

Opción B: Lanzar una Nueva Ventana (Modal o Secundaria)

Crea un nuevo objeto Stage. Usando initModality(Modality.APPLICATION_MODAL) bloqueas la ventana padre hasta que el usuario cierre el diálogo emergente.

LanzadorModal.java 
import javafx.fxml.FXMLLoader;
import javafx.scene.Parent;
import javafx.scene.Scene;
import javafx.stage.Modality;
import javafx.stage.Stage;
import java.io.IOException;

public class LauncherHelper {

    public static void abrirVentanaModal(String rutaFxml, String titulo, Stage ownerStage) {
        try {
            FXMLLoader loader = new FXMLLoader(LauncherHelper.class.getResource(rutaFxml));
            Parent root = loader.load();

            Stage modalStage = new Stage();
            modalStage.setTitle(titulo);
            modalStage.setScene(new Scene(root));
            
            // Configurar como ventana modal dependiente del padre
            modalStage.initModality(Modality.WINDOW_MODAL);
            modalStage.initOwner(ownerStage);
            modalStage.setResizable(false);
            
            modalStage.showAndWait(); // Espera a que se cierre
        } catch (IOException e) {
            e.printStackTrace();
        }
    }
}

8. Clase Principal: Application y Método start()

App.java (Entry Point) 
import javafx.application.Application;
import javafx.fxml.FXMLLoader;
import javafx.scene.Parent;
import javafx.scene.Scene;
import javafx.stage.Stage;

public class App extends Application {

    @Override
    public void start(Stage primaryStage) throws Exception {
        // Carga la vista principal diseñada en Scene Builder
        Parent root = FXMLLoader.load(getClass().getResource("/vistas/MainView.fxml"));
        
        Scene scene = new Scene(root);
        primaryStage.setTitle("Sistema JavaFX Profesional");
        primaryStage.setScene(scene);
        primaryStage.show();
    }

    public static void main(String[] args) {
        launch(args); // Lanza el ciclo de vida JavaFX
    }
}

Checklist Rápido para Evitar Errores Comunes

fx:id repetido o ausente: Asegúrate de que el fx:id en Scene Builder coincida exactamente con el nombre de la variable anotada con @FXML en Java.
Ruta del FXML: Comprueba siempre que el archivo FXML esté dentro del directorio de recursos (ej: src/main/resources/).
Visibilidad de @FXML: Los campos y métodos pueden ser private siempre que lleven la anotación @FXML.
Platform.runLater(): Si actualizas componentes visuales desde hilos secundarios o tareas en segundo plano, siempre envuélvelo en Platform.runLater(() -> { ... }).
