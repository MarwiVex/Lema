19. JDBC, Singleton y Arquitectura ADMON/DAO (MySQL + SQLite)

JDBC (Java Database Connectivity) es la API oficial de Java (paquete java.sql) que permite que tu código se comunique con cualquier motor de base de datos relacional usando exactamente las mismas clases (Connection, PreparedStatement, ResultSet). En esta sección analizaremos a fondo la arquitectura completa del repositorio BaseDatos.

2. Las 4 Clases Esenciales de java.sql

1. DriverManager

Lee el prefijo de la URL (jdbc:mysql:... o jdbc:sqlite:...) y abre la conexión con DriverManager.getConnection(...).

2. Connection

Representa la sesión activa con la BD. A partir de ella preparamos sentencias con conexion.prepareStatement(sql).

3. PreparedStatement

Ejecuta consultas de lectura con executeQuery() (devuelve un ResultSet) o modificaciones con execute() / executeUpdate().

4. ResultSet

Cursor que apunta a las filas devueltas por un SELECT. Se recorre con while(rs.next()) extrayendo columnas con getInt("col"), getString("col"), etc.

3. Datos.java: Patrón Singleton con Failover Automático (MySQL → SQLite)

Observa la elegancia de la clase Datos.java en el paquete ADMON:

  • Patrón Singleton: Su constructor es private y expone Datos.getInstance() para abrir una única conexión durante toda la ejecución.
  • Conexión Híbrida Resiliente (Failover): Primero intenta conectarse al servidor principal MySQL (urlServer). Si el servidor XAMPP está apagado o no hay red, captura el SQLException y en el bloque catch se conecta automáticamente a la base de datos local SQLite (informacion.db). ¡La aplicación sigue funcionando sin caerse!
ADMON/Datos.java (Singleton + Failover MySQL a SQLite) 
package com.example.basedatos.ADMON;

import java.io.IOException;
import java.io.InputStream;
import java.sql.*;
import java.util.Properties;

public class Datos {
    private static Datos datos = null;
    private Connection conexion;

    private Datos() {
        Properties propiedades = new Properties();
        try (InputStream input = Datos.class.getResourceAsStream("/database.properties")) {
            propiedades.load(input);
        } catch (IOException e) {
            System.err.println(e.getMessage());
        }

        String urlServer = propiedades.getProperty("db.url", propiedades.getProperty("url", "jdbc:mysql://localhost:3306/informacion_db"));
        String user = propiedades.getProperty("db.user", propiedades.getProperty("user", "root"));
        String password = propiedades.getProperty("db.password", propiedades.getProperty("password", ""));
        String urlLocal = propiedades.getProperty("db.local.url", propiedades.getProperty("db.url.local", "jdbc:sqlite:informacion.db"));

        try {
            // 1. Intentar conectar al servidor principal (MySQL)
            conexion = DriverManager.getConnection(urlServer, user, password);
            System.out.println("bd conectada al servidor (MySQL)");
        } catch (SQLException e) {
            System.err.println("MySQL no disponible (" + e.getMessage() + "). Conectando a SQLite local...");
            try {
                // 2. Respaldo automático: conectar al archivo local SQLite
                conexion = DriverManager.getConnection(urlLocal);
                System.out.println("bd conectada en modo local (SQLite)");
            } catch (SQLException ex) {
                System.err.println(ex.getMessage());
            }
        }
    }

    public static Datos getInstance() {
        if (datos == null) {
            datos = new Datos();
        }
        return datos;
    }

    // Para sentencias SELECT (devuelve las filas en un ResultSet)
    public ResultSet ejecutarConsulta(String consulta) {
        ResultSet resultado = null;
        try {
            resultado = this.conexion.prepareStatement(consulta).executeQuery();
        } catch (SQLException e) {
            System.err.println(e.getMessage());
        }
        return resultado;
    }

    // Para sentencias INSERT, UPDATE o DELETE
    public boolean ejecutarInstruccion(String consulta) {
        try {
            this.conexion.prepareStatement(consulta).execute();
        } catch (SQLException e) {
            System.err.println(e.getMessage());
        }
        return true;
    }

    public Connection getConexion() {
        return this.conexion;
    }
}

4. Prueba del Singleton con DatosMYSQL.java y EjemploMYSQL.java

Observa cómo EjemploMYSQL.java solicita 10 veces la conexión dentro de un bucle y comprueba con stream().allMatch(...) que las 10 referencias apuntan exactamente al mismo objeto Connection:

EjemploMYSQL.java (Comprobación de instancia única) 
package com.example.basedatos;

import java.sql.Connection;
import java.util.LinkedList;
import java.util.Scanner;

public class EjemploMYSQL {
    public static void main(String[] args) {
        try {
            LinkedList conexiones = new LinkedList<>();

            System.out.println("=== Probando el modelo Singleton con DatosMYSQL ===");
            for (int i = 0; i < 10; i++) {
                // Obtenemos la conexión a través de la instancia Singleton
                Connection con = DatosMYSQL.getInstance().getConexion();
                conexiones.add(con);
                System.out.println("Iteración " + (i + 1) + " -> Referencia de conexión: " + con);
            }

            if (!conexiones.isEmpty() && conexiones.getFirst() != null) {
                boolean todasIguales = conexiones.stream().allMatch(c -> c == conexiones.getFirst());
                System.out.println("¿Todas las referencias son exactamente la misma instancia?: " + todasIguales);
            }

            System.out.println("Presiona ENTER para cerrar la conexión y salir...");
            new Scanner(System.in).nextLine();

            if (DatosMYSQL.getInstance().getConexion() != null && !DatosMYSQL.getInstance().getConexion().isClosed()) {
                DatosMYSQL.getInstance().getConexion().close();
                System.out.println("Conexión cerrada exitosamente.");
            }
        } catch (Exception e) {
            e.printStackTrace();
        }
    }
}

5. Separación en Capas: POJOs, Clase Administradora (AdmonCafe) y Controlador JavaFX

Un proyecto limpio nunca mezcla sentencias SQL dentro de los botones de la interfaz gráfica. En su lugar, divide el código en tres capas:

  1. Paquete POJO (Cafe.java, VariedadCafe.java): Clases simples con atributos, constructores, getters/setters y toString() que representan una fila de cada tabla.
  2. Paquete ADMON (AdmonCafe.java, AdmonVariedadCafe.java): Clases administradoras (Data Access Objects) que traducen objetos Java en sentencias INSERT, UPDATE, DELETE y convierten el ResultSet de SELECT en una LinkedList<Cafe>.
  3. Controlador JavaFX (CafeController.java): Gestiona los eventos de la vista y llama a los métodos de AdmonCafe.
ADMON/AdmonCafe.java (CRUD completo contra la BD) 
package com.example.basedatos.ADMON;

import com.example.basedatos.POJO.Cafe;
import java.sql.ResultSet;
import java.sql.SQLException;
import java.util.LinkedList;

public class AdmonCafe {
    private Datos datos;

    public AdmonCafe() {
        datos = Datos.getInstance();
    }

    public void agregar(Cafe cafe) throws Exception {
        String consulta = String.format(
            "INSERT INTO Cafe(Productor, VariedadCafe, Cantidad) VALUES('%s', %d, %f)",
            cafe.getProductor(), cafe.getVariedadCafe(), cafe.getCantidad()
        );
        datos.ejecutarInstruccion(consulta);
    }

    public void editar(Cafe cafe) throws Exception {
        String consulta = String.format(
            "UPDATE Cafe SET Productor='%s', VariedadCafe=%d, Cantidad=%f WHERE IDCafe=%d",
            cafe.getProductor(), cafe.getVariedadCafe(), cafe.getCantidad(), cafe.getIdcafe()
        );
        datos.ejecutarInstruccion(consulta);
    }

    public void borrar(Integer idCafe) throws Exception {
        String consulta = String.format("DELETE FROM Cafe WHERE IDCafe=%d", idCafe);
        datos.ejecutarInstruccion(consulta);
    }

    public LinkedList obtenerCafe() throws Exception {
        LinkedList Cafes = new LinkedList<>();
        String consulta = "SELECT * FROM Cafe";
        try {
            ResultSet resultado = datos.ejecutarConsulta(consulta);
            if (resultado != null) {
                // Avanzamos fila por fila con resultado.next()
                while (resultado.next()) {
                    Cafes.add(new Cafe(
                        resultado.getInt("IDCafe"),
                        resultado.getString("Productor"),
                        resultado.getInt("VariedadCafe"),
                        resultado.getFloat("Cantidad")
                    ));
                }
                resultado.close(); // Importante liberar el cursor al terminar
            }
        } catch (SQLException e) {
            System.err.println("Error al cargar Cafes: " + e.getMessage());
        }
        return Cafes;
    }
}

            AdministradorCafe.editar(cafe);

            limpiarCampos();

        }

    }

6. ¿Y cómo se hace SIN Singleton? PreparedStatement con ? (Placeholders)

En los ejemplos anteriores del repositorio BaseDatos, vimos que AdmonCafe.java armaba las consultas usando String.format("INSERT INTO Cafe ... VALUES('%s', %d, %f)", ...) apoyándose en la conexión única y global de Datos.getInstance(). Aunque esa forma es muy rápida para prácticas escolares, en proyectos profesionales NO se hace así. Veamos por qué y cómo se programa el enfoque estándar de la industria.

1. El Peligro Mortal: Inyección SQL (SQL Injection)

Cuando usas String.format o concatenación con +, el motor de base de datos interpreta lo que escriba el usuario como código SQL ejecutable.

// Si el usuario escribe esto en textFieldProductor:
"Don Pedro', 1, 0); DROP TABLE Cafe; --"

// String.format produce este comando letal:
INSERT INTO Cafe(Productor, VariedadCafe, Cantidad)
VALUES('Don Pedro', 1, 0); DROP TABLE Cafe; --', 1, 0);

¡La tabla Cafe completa es eliminada al instante! Además, si un cliente se apellida O'Connor o D'Angelo, la comilla simple rompe la sintaxis y lanza una excepción SQLException: syntax error.

2. ¿Por qué prescindir del Singleton global?

Tener un Singleton con una sola conexión abierta para siempre tiene riesgos en producción:

  • Conexión caída o timeout: Si MySQL o SQLite cierran la conexión por inactividad, toda la aplicación deja de funcionar porque el Singleton nunca la reabre.
  • Concurrencia: Si dos hilos o pantallas intentan usar la misma Connection al mismo tiempo, las transacciones se cruzan.
  • La Solución Estándar: Cada operación abre su propia conexión bajo demanda y la cierra inmediatamente al terminar, o mejor aún, la pide a un Pool de Conexiones (como HikariCP).

Anatomía de PreparedStatement con Comodines ? (Placeholders)

Con PreparedStatement, la sentencia SQL se escribe con signos de interrogación ? en cada valor variable. Luego se usan los métodos tipados setX(indice, valor) para inyectar los datos:

1 Plantilla SQL con comodines ? 
String sql = "INSERT INTO Cafe (Productor, VariedadCafe, Cantidad) VALUES (?, ?, ?)";
PreparedStatement ps = con.prepareStatement(sql);

El motor de la base de datos compila primero la consulta antes de recibir los valores. Ningún texto ingresado podrá alterar la lógica del comando SQL.

2 Asignación con setX(índice, valor) 
// ¡REGLA DE ORO DE JDBC! Los índices empiezan en 1 (NO en 0)
ps.setString(1, cafe.getProductor());    // 1er ? -> VARCHAR
ps.setInt(2, cafe.getVariedadCafe());    // 2do ? -> INTEGER
ps.setFloat(3, cafe.getCantidad());      // 3er ? -> FLOAT

ps.executeUpdate(); // Ejecuta INSERT, UPDATE o DELETE

Si cafe.getProductor() vale "O'Connor" o incluye código malicioso, el driver escapa todo de forma nativa a nivel binario.

Código Completo: CafeDAO.java (Sin Singleton + try-with-resources)

Observa cómo luce la clase administradora profesional: ya no llama a Datos.getInstance(). En su lugar, usa un método conectar() y la sentencia try (...) con recursos automáticos, la cual cierra la Connection, el PreparedStatement y el ResultSet automáticamente sin riesgo de fugas de memoria:

src/main/java/com/example/basedatos/ADMON/CafeDAO.java (Enfoque Sin Singleton) 
package com.example.basedatos.ADMON;

import com.example.basedatos.POJO.Cafe;
import java.sql.Connection;
import java.sql.DriverManager;
import java.sql.PreparedStatement;
import java.sql.ResultSet;
import java.sql.SQLException;
import java.util.LinkedList;

public class CafeDAO {
    // Datos de conexión (pueden venir de un .properties o pasarse directo)
    private static final String URL_SQLITE = "jdbc:sqlite:informacion.db";
    private static final String URL_MYSQL = "jdbc:mysql://localhost:3306/informacion_db";
    private static final String USER = "root";
    private static final String PASS = "";

    // Método que abre una conexión fresca bajo demanda
    private Connection obtenerConexion() throws SQLException {
        try {
            // Intentar MySQL primero
            return DriverManager.getConnection(URL_MYSQL, USER, PASS);
        } catch (SQLException e) {
            // Respaldo local a SQLite si MySQL no está encendido
            return DriverManager.getConnection(URL_SQLITE);
        }
    }

    // 1. AGREGAR (INSERT) con comodines ? y PreparedStatement
    public boolean agregar(Cafe cafe) {
        String sql = "INSERT INTO Cafe (Productor, VariedadCafe, Cantidad) VALUES (?, ?, ?)";

        // try-with-resources: ¡Garantiza que conexion y ps se cierren solos al terminar!
        try (Connection con = obtenerConexion();
             PreparedStatement ps = con.prepareStatement(sql)) {

            // Asignación de parámetros por posición (inicia en 1)
            ps.setString(1, cafe.getProductor());
            ps.setInt(2, cafe.getVariedadCafe());
            ps.setFloat(3, cafe.getCantidad());

            // executeUpdate() devuelve cuántas filas fueron afectadas (1 si se guardó bien)
            return ps.executeUpdate() > 0;
        } catch (SQLException e) {
            System.err.println("Error al agregar cafe: " + e.getMessage());
            return false;
        }
    }

    // 2. EDITAR (UPDATE) con comodines ?
    public boolean editar(Cafe cafe) {
        String sql = "UPDATE Cafe SET Productor = ?, VariedadCafe = ?, Cantidad = ? WHERE IDCafe = ?";

        try (Connection con = obtenerConexion();
             PreparedStatement ps = con.prepareStatement(sql)) {

            ps.setString(1, cafe.getProductor());
            ps.setInt(2, cafe.getVariedadCafe());
            ps.setFloat(3, cafe.getCantidad());
            ps.setInt(4, cafe.getIdcafe()); // 4to ? es la condición del WHERE

            return ps.executeUpdate() > 0;
        } catch (SQLException e) {
            System.err.println("Error al editar cafe: " + e.getMessage());
            return false;
        }
    }

    // 3. BORRAR (DELETE) con comodín ?
    public boolean borrar(int idCafe) {
        String sql = "DELETE FROM Cafe WHERE IDCafe = ?";

        try (Connection con = obtenerConexion();
             PreparedStatement ps = con.prepareStatement(sql)) {

            ps.setInt(1, idCafe);

            return ps.executeUpdate() > 0;
        } catch (SQLException e) {
            System.err.println("Error al borrar cafe: " + e.getMessage());
            return false;
        }
    }

    // 4. CONSULTAR (SELECT) y mapeo de ResultSet
    public LinkedList obtenerTodos() {
        LinkedList lista = new LinkedList<>();
        String sql = "SELECT IDCafe, Productor, VariedadCafe, Cantidad FROM Cafe";

        try (Connection con = obtenerConexion();
             PreparedStatement ps = con.prepareStatement(sql);
             ResultSet rs = ps.executeQuery()) { // Para lectura usamos executeQuery()

            while (rs.next()) {
                lista.add(new Cafe(
                    rs.getInt("IDCafe"),
                    rs.getString("Productor"),
                    rs.getInt("VariedadCafe"),
                    rs.getFloat("Cantidad")
                ));
            }
        } catch (SQLException e) {
            System.err.println("Error al consultar cafes: " + e.getMessage());
        }
        return lista;
    }
}

Tabla Comparativa: Enfoque Singleton vs Enfoque PreparedStatement Estándar

Característica Enfoque con Singleton (Datos.java) Enfoque Estándar Sin Singleton (CafeDAO)
Ciclo de vida de la conexión Una sola conexión global estática que nunca se cierra. Se abre y se cierra en cada operación con try-with-resources (o mediante Pool).
Construcción de la consulta Concatenación de cadenas con String.format(...). Plantilla precompilada con comodines ? (Placeholders).
Seguridad (Inyección SQL) Vulnerable a código malicioso en campos de texto. 100% Inmune; los datos viajan separados del comando.
Caracteres como comillas simples (') Rompe la consulta con error de sintaxis SQL. Se escapan de forma totalmente transparente y automática.
Rendimiento La base de datos recompila la consulta cada vez. El motor reutiliza el plan de ejecución precompilado de la sentencia.
Ejecución de cambios ps.execute() genérico. ps.executeUpdate() (devuelve filas afectadas para validar éxito).
