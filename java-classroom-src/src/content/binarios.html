Archivos Binarios & Serialización

La serialización de objetos en Java representa una biyección computacional: mapea el estado estructurado de un objeto residente en la memoria RAM (sus grafos de referencias y datos primitivos) hacia una secuencia lineal de bytes en disco, y viceversa. A diferencia de los archivos de texto plano, los archivos binarios no son legibles por el ser humano, pero son extremadamente eficientes para la máquina, ya que omiten las sobrecargas de conversión de tipos (parsing) y de codificación de caracteres.

1. La Entidad: Interfaz Serializable y serialVersionUID

Contrato de Persistencia

Para que la Máquina Virtual de Java (JVM) autorice la transformación de una clase a una ráfaga de bytes, la clase debe implementar la interfaz marcadora java.io.Serializable. Al ser una interfaz sin métodos, le indica al compilador que el estado de las instancias de esta clase puede ser volcado a disco de manera segura.

serialVersionUID

Actúa como una firma o hash de versión estructural de la clase. Si guardas un objeto hoy y mañana agregas un nuevo atributo, la JVM comparará los serialVersionUID. Si no coinciden, se lanzará una InvalidClassException para evitar corrupción de memoria.

Modificador transient

La palabra reservada transient excluye explícitamente un atributo del proceso de serialización. Al reconstruir el objeto desde disco, el valor de ese campo será null (o 0), ignorando lo que tenía antes de guardar.

JugueteBinario.java 
import java.io.Serializable;

// 1. Declarar la interfaz marcadora Serializable
public class JugueteBinario implements Serializable {
    
    // 2. Identificador de versión para control de cambios estructurales
    private static final long serialVersionUID = 1L; 

    private String codigo;
    private String nombre;
    private int edicion;
    
    // La palabra clave 'transient' excluye explícitamente esta variable de la serialización.
    // Al deserializar, su valor volverá al valor por defecto de Java (null o 0).
    private transient String datoTemporal; 

    public JugueteBinario(String codigo, String nombre, int edicion) {
        this.codigo = codigo;
        this.nombre = nombre;
        this.edicion = edicion;
        this.datoTemporal = "No persistente en disco";
    }

    @Override
    public String toString() {
        return String.format("Juguete [Código: %s, Nombre: %s, Edición: %d | Temp: %s]", 
                             this.codigo, this.nombre, this.edicion, this.datoTemporal);
    }
}

2. Flujos de I/O Binarios y Patrón Decorator

Al trabajar con datos binarios, sustituimos los lectores de texto (FileWriter / FileReader) por flujos de bytes puros: FileOutputStream y FileInputStream. Sobre ellos aplicamos el patrón Decorator envolviéndolos en ObjectOutputStream y ObjectInputStream.

ObjectOutputStream

Recibe instancias de clases serializables y las convierte en una secuencia de bytes mediante writeObject(), canalizándolas directamente a un FileOutputStream.

ObjectInputStream

Lee el flujo continuo de bytes de un FileInputStream y reconstruye el objeto original en la memoria Heap usando readObject().

3. Ejemplo Práctico: Serializar y Deserializar Colecciones

GestorBinario.java 
import java.io.*;
import java.util.LinkedList;

public class GestorBinario {

    // =====================================================================
    // ESCRITURA: Serializando una Colección entera
    // =====================================================================
    public static void guardarClaseEntera(String ruta, LinkedList lista) {
        File archivo = new File(ruta);

        // Try-with-resources: ObjectOutputStream envuelve a FileOutputStream
        try (FileOutputStream fos = new FileOutputStream(archivo);
             ObjectOutputStream oos = new ObjectOutputStream(fos)) {

            // writeObject() toma cualquier objeto que implemente Serializable.
            // Dado que LinkedList implementa Serializable y JugueteBinario también,
            // podemos volcar la estructura de datos completa en una sola llamada de O(1).
            oos.writeObject(lista);
            
            System.out.println("Estructura de datos serializada correctamente en: " + ruta);

        } catch (IOException e) {
            System.err.println("Error crítico de I/O al escribir archivo binario: " + e.getMessage());
        }
    }

    // =====================================================================
    // LECTURA: Deserializando y reconstruyendo la memoria
    // =====================================================================
    @SuppressWarnings("unchecked") // Suprimimos el warning del casteo genérico
    public static LinkedList leerClaseEntera(String ruta) {
        LinkedList listaReconstruida = new LinkedList<>();
        File archivo = new File(ruta);

        if (!archivo.exists()) return listaReconstruida;

        try (FileInputStream fis = new FileInputStream(archivo);
             ObjectInputStream ois = new ObjectInputStream(fis)) {

            // readObject() retorna un tipo genérico 'Object'. 
            // Debemos aplicar un casting explícito para mapearlo a nuestra estructura original.
            Object objetoLeido = ois.readObject();
            
            if (objetoLeido instanceof LinkedList) {
                listaReconstruida = (LinkedList) objetoLeido;
                System.out.println("Des-serialización exitosa. Objetos en memoria: " + listaReconstruida.size());
            }

        } catch (FileNotFoundException e) {
            System.err.println("Archivo no localizado: " + e.getMessage());
        } catch (IOException e) {
            System.err.println("Error de lectura binaria: " + e.getMessage());
        } catch (ClassNotFoundException e) {
            // Excepción exclusiva de binarios: ocurre si el archivo contiene una clase
            // que ya no existe en el código fuente actual de la aplicación.
            System.err.println("Incompatibilidad de clases en tiempo de ejecución: " + e.getMessage());
        }

        return listaReconstruida;
    }

    // =====================================================================
    // MÉTODO MAIN DE PRUEBA
    // =====================================================================
    public static void main(String[] args) {
        String archivoBinario = "juguetes.dat"; // Convención: .dat o .bin para binarios

        // 1. Instanciamos objetos en RAM
        LinkedList inventario = new LinkedList<>();
        inventario.add(new JugueteBinario("123", "Darth Vader Mafex", 1));
        inventario.add(new JugueteBinario("456", "Yoda Mafex", 2));

        // 2. Volcamos la memoria RAM al Disco (Persistencia Binaria)
        guardarClaseEntera(archivoBinario, inventario);

        // 3. Simulamos un reinicio del sistema limpiando la lista original
        inventario = null;

        // 4. Recuperamos el estado directamente desde el disco sin hacer parsing manual
        LinkedList inventarioRecuperado = leerClaseEntera(archivoBinario);

        // Comprobación de integridad
        for (JugueteBinario j : inventarioRecuperado) {
            System.out.println(j.toString());
        }
    }
}

Análisis Interno & Gestión de Excepciones

writeObject(Object obj):

Ejecuta un análisis exhaustivo (reflexión) del objeto proporcionado. Si es una colección (como LinkedList), itera internamente sobre sus nodos y verifica que cada elemento también sea Serializable. Escribe secuencialmente la metainformación de la clase y los valores binarios de sus atributos.

readObject():

Realiza el proceso inverso. Lee primero los metadatos de la clase desde el archivo binario, verifica el serialVersionUID contra la clase cargada en la JVM, reserva memoria en el Heap y asigna los valores bit a bit.

Gestión de EOFException (End Of File):

Si guardas objetos de manera individual llamando a oos.writeObject(juguete) múltiples veces en lugar de guardar una colección completa, al leerlos deberás usar un bucle while(true) y capturar la excepción EOFException para salir del bucle. Los archivos binarios no poseen un delimitador o marcador "fin de línea" (como null en readLine()). Volcar la colección completa (Collection) elimina este problema y simplifica enormemente el código.
