Programación Orientada a Objetos (POO)

La Programación Orientada a Objetos (POO) es el paradigma principal en Java. Se basa en organizar el código modelando entidades del mundo real llamadas "objetos".

Conceptos Fundamentales

Clase

Plantilla o molde abstracto que define los atributos (datos/estado) y métodos (comportamientos) que compartirán los objetos creados a partir de ella.

Objeto

Unidad básica en POO que combina estado (variables) y comportamiento (funciones).

Instancia

La materialización concreta e individualizada en memoria de una clase. (Ocurre cuando utilizas la palabra reservada new).

Método

Subrutina o función definida dentro de una clase que opera sobre los datos del objeto o realiza una tarea específica.

Los 4 Pilares de la POO

Abstracción

Proceso de modelar únicamente las características y comportamientos esenciales de una entidad del mundo real, omitiendo detalles irrelevantes de implementación.

Encapsulamiento

Ocultamiento de los detalles internos del estado de un objeto, exponiendo solo interfaces públicas seguras para interactuar con él (control de acceso mediante modificadores como private, protected, public).

Herencia

Mecanismo que permite a una nueva clase (subclase) derivar atributos y métodos de una clase existente (superclase), promoviendo la reutilización de código.

Polimorfismo

Capacidad de tratar objetos de distintas subclases como instancias de una superclase común, permitiendo que un mismo método ejecute comportamientos diferentes según el objeto receptor (mediante overriding o overloading).

Ejemplo Corregido en Java

Para que el programa sea ejecutable de forma estándar en Java, la firma del método main requiere public static void main(String[] args), los identificadores de variables deben seguir las convenciones de camelCase, la sintaxis de invocar métodos exige paréntesis (), y el formato de los especificadores (%d, %s) debe coincidir rigurosamente con los tipos de datos.

Alumno.java 
class Alumno {
    // Atributos de clase
    String nombre;
    int edad;
    int nua;

    // Métodos
    String imprimir() {
        return String.format("%d, %s, %d\n", nua, nombre, edad);
    }

    void imprimirClase() {
        System.out.printf("%s, %d, %d\n", nombre, edad, nua);
    }
}
Principal.java 
public class Principal {
    public static void main(String[] args) {
        // Creación e instanciación del objeto alumno1
        Alumno alumno1 = new Alumno();

        // Asignación de valores
        alumno1.edad = 18;
        alumno1.nombre = "Hola";
        alumno1.nua = 676767;

        // Invocación de métodos
        System.out.print(alumno1.imprimir());
        alumno1.imprimirClase();
    }
}

Nota para compilar: En este ejemplo básico, ambas clases pueden ir en el mismo archivo para el compilador web, asegurándote que sólo la clase Principal tenga la palabra public.

Importancia de private vs public (Encapsulamiento y Protección)

El verdadero objetivo del Encapsulamiento no es solo esconder código, sino garantizar la integridad de los datos. Al marcar un atributo como private, impedimos que cualquier código externo modifique el valor directamente sin pasar por nuestras reglas de negocio.

Con Atributos Públicos (Sin Control)

Si la variable edad fuera public, desde cualquier parte del programa podrían asignarle valores absurdos (por ejemplo: alumno1.edad = -50; o alumno1.edad = 999;). No existe ninguna barrera para evitar datos corruptos o imposibles.

Con Atributos Privados y Setters (Con Protección)

Al definir private int edad;, forzamos el uso de un método setter (setEdad(valor)) donde definimos una condición de rango. Sin importar de dónde se intente modificar la edad, la clase rechazará valores fuera de la regla (ej. 15 a 100 años).

Ejemplo Práctico: Validación de Rango con Getters y Setters

Observa cómo la clase Alumno restringe sus atributos con private y expone métodos public (Getters y Setters) para leer y validar la información de manera segura:

Alumno.java (Encapsulado) 
public class Alumno {
    // Atributos PRIVADOS (Protegidos contra acceso directo)
    private String nombre;
    private int edad;
    private int nua;

    // Setters (Métodos para modificar datos con validación)
    public void setNombre(String valor) {
        this.nombre = valor;
    }

    public void setEdad(int valor) {
        // Regla de validación: La edad debe estar en un rango permitido (15 a 100 años)
        if (valor >= 15 && valor <= 100) {
            this.edad = valor;
        } else {
            System.out.println("⚠️ Error: La edad " + valor + " no está en el rango permitido (15-100). No se asignó.");
        }
    }

    public void setNUA(int valor) {
        this.nua = valor;
    }

    // Getters (Métodos públicos para leer valores)
    public String getNombre() {
        return this.nombre;
    }

    public int getEdad() {
        return this.edad;
    }

    public int getNUA() {
        return this.nua;
    }

    // Método de impresión
    public String imprimir() {
        return String.format("%d, %s, %d \n", nua, nombre, edad);
    }
}
Principal.java 
public class Principal {
    public static void main(String[] args) {
        Alumno alumno1 = new Alumno();

        // 1. Asignaciones válidas usando Setters
        alumno1.setNombre("Juan");
        alumno1.setEdad(18); // Válido (dentro del rango 15-100)
        alumno1.setNUA(213232);

        System.out.print(alumno1.imprimir());

        // 2. Intento de asignación fuera de rango
        alumno1.setEdad(200); // ❌ Error de validación: Se rechaza el 200 y se conserva 18

        // 3. Intento de acceso directo si la variable fuera private
        // alumno1.edad = 250; ❌ Error de compilación: 'edad' tiene acceso privado en Alumno
    }
}

Punto Clave: Si los atributos fueran public, cualquier programador podría hacer alumno1.edad = 250; saltándose la condición. Con private y setEdad(), aseguramos que la regla de negocio se cumpla SIEMPRE, sin importar desde dónde se invoque.
