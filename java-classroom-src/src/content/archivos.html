Archivos, Entradas y Salidas (I/O)

El manejo de archivos en Java es crucial para la persistencia de datos. Hasta ahora, todos los datos en las variables se pierden cuando el programa termina. Con el paquete java.io, podemos guardar información en el disco duro y recuperarla posteriormente.

1. La clase File

Representación en Memoria

La clase File NO representa el contenido del archivo, sino la ruta o el enlace hacia el archivo en el sistema operativo. Puede apuntar a un archivo existente, a un directorio, o a un archivo que aún no existe y planeamos crear.

// Importación necesaria import java.io.File;

// Crear la referencia al archivo File archivo = new File("datos.txt");

// Métodos útiles de File System.out.println(archivo.exists()); // ¿Existe físicamente?
System.out.println(archivo.isFile()); // ¿Es un archivo normal?
System.out.println(archivo.isDirectory()); // ¿Es una carpeta?

2. Escritura: FileWriter y BufferedWriter

Para escribir texto en un archivo, usamos clases de tipo Writer.

FileWriter (Sin Buffer)

Escribe los datos directamente en el disco duro carácter por carácter. Es muy lento porque el disco duro es el componente más lento de la computadora. Hacer múltiples viajes pequeños al disco penaliza el rendimiento.

BufferedWriter (Con Buffer)

Actúa como un "carrito de compras" en la memoria RAM. Acumula todos los textos que quieres escribir y, cuando el carrito está lleno (o cuando llamas a flush() o cierras el archivo), hace un único viaje al disco duro. Es mucho más rápido y eficiente.

Escritura.java 
import java.io.*;

public class Escritura {
    public static void guardar(String nombreArchivo) {
        File nuevo = new File(nombreArchivo);
        
        // El try-with-resources cierra automáticamente el archivo al terminar
        try (FileWriter fw = new FileWriter(nuevo);
             BufferedWriter bw = new BufferedWriter(fw)) {
             
            bw.write("JUGUETE|SKU123|ACTIVO|Pelota|Hasbro|1");
            bw.newLine(); // Agrega un salto de línea compatible con cualquier SO
            
            // También puedes usar String.format para escribir datos formateados
            bw.write(String.format("%s|%s|%s|%s|%d", "PELICULA", "SKU999", "ACTIVO", "Matrix", 1999));
            
        } catch (IOException e) {
            System.err.println("Error al intentar escribir en el disco.");
        }
    }
}

3. Lectura: FileReader y BufferedReader

De manera análoga a la escritura, para leer usamos el FileReader envuelto en un BufferedReader, el cual nos proporciona el útil método readLine() para leer el archivo línea por línea hasta llegar al final (que devuelve null).

Lectura.java 
import java.io.*;
import java.util.regex.Pattern;

public class Lectura {
    public static void leerArchivo(String nombreArchivo, String separador) {
        File archivo = new File(nombreArchivo);
        // Pattern.quote asegura que si el separador es un caracter especial (como | o .), se interprete literalmente
        String sep = Pattern.quote(separador);

        // Se usa try-with-resources. El BufferedReader se encarga de cerrar el FileReader subyacente.
        try (BufferedReader br = new BufferedReader(new FileReader(archivo))) {
            String linea;
            
            // Leemos línea por línea hasta que devuelva null (fin del archivo)
            while ((linea = br.readLine()) != null) {
                // Separamos la línea usando el separador especificado
                String[] datos = linea.split(sep);
                
                String tipo = datos[0];
                System.out.println("Cargando tipo: " + tipo);
                // Aquí podrías usar un switch para instanciar el objeto correcto según 'tipo'
            }
            
        } catch (FileNotFoundException e) {
            System.err.println("El archivo especificado no existe: " + nombreArchivo);
        } catch (IOException e) {
            System.err.println("Error de I/O al leer el archivo.");
        }
    }
}

Excepciones Checked de I/O

El manejo de archivos te obliga obligatoriamente (son Checked Exceptions) a usar bloques try-catch.

FileNotFoundException:

Se lanza específicamente cuando intentas leer (FileReader) un archivo que no existe en la ruta proporcionada. (Al escribir, FileWriter suele crear el archivo si no existe, a menos que la carpeta tampoco exista o no haya permisos).

IOException:

La excepción padre para problemas de entrada/salida. Puede lanzarse si el disco está lleno, si se pierde la conexión a una unidad de red, o si el archivo está bloqueado por otro programa.
